# Research: hvordan komme i gang (13.11.2026)

Formål: kartlegge byggeklossene for en norsk personal finance-app før vi tar designvalg.
Kilder er listet nederst. Punkter merket ⚠️ er ikke bekreftet fra offisiell kilde.

## 1. Hvordan få inn bankdata (det viktigste valget)

| Metode | Hvordan | Fordeler | Ulemper |
|---|---|---|---|
| **A. Fileksport fra nettbanken** | Last ned CSV/Excel fra DNB, Nordea, SpareBank 1 osv. og importer | Gratis, ingen avtaler, fungerer med alle banker, full kontroll | Manuelt arbeid; hvert bankformat må ha egen parser |
| **B. PSD2 via aggregator (Enable Banking)** | Kobler kontoer med BankID via redirect, henter transaksjoner over API | Automatisk; én API for mange norske banker | Samtykke må fornyes jevnlig; avhengig av tredjepart |
| **C. PSD2 direkte mot bankene** | developer.dnb.no, Nordea API Market osv. | Ingen mellomledd | Krever PSD2-lisens fra Finanstilsynet + eIDAS-sertifikat. Urealistisk for et privat prosjekt |
| **D. Manuell registrering** | Skriv inn selv | Enklest | Ingen vil gjøre det over tid |

Funn:
- **Enable Banking** har gratis bruk for *private personer til eget bruk*: produksjonsappen kan bare hente data fra kontoer du selv har koblet til ("linked accounts"). Dette er den mest realistiske automatiske løsningen for oss. Hvilke norske banker som er dekket må sjekkes i kontrollpanelet.
- **GoCardless Bank Account Data (tidligere Nordigen)**, som mange GitHub-prosjekter bruker, har ifølge flere rapporter stengt for nye brukere ⚠️. Repoer som bygger på den vil vi ikke kunne kopiere direkte.
- **Sbanken** ble en del av DNB i mai 2023. Det gamle, populære Sbanken-API-et (mange hobby-repoer bygger på det) er usikkert om fortsatt finnes ⚠️. Ikke bygg på det.
- Kun en bank med PSD2-lisens eller en lisensiert aggregator kan hente data via PSD2. Hvis appen en dag skal brukes av *andre* enn oss selv, endrer det hele det juridiske bildet.

**Anbefaling for start:** A (fil-import) først, med en datamodell som tåler at B (Enable Banking) kobles på senere.

## 2. Offentlige norske datakilder (gratis, åpne)

- **Norges Bank API** (data.norges-bank.no): valutakurser, styringsrente, Nowa. SDMX/REST, JSON/CSV, ingen nøkkel.
- **SSB Statistikkbanken API** (PxWeb): KPI (inflasjon) m.m. Åpent, ingen registrering. Det gamle "ferdige datasett"-API-et ble lagt ned 31.12.2025.
- **Finansportalen** (Forbrukerrådet): sammenligner renter på lån/sparing. Fant ikke noe offentlig API ⚠️.

## 3. Norske regler og særtrekk appen bør forstå

Disse må vi verifisere mot Skatteetaten før vi bygger dem. Satser endres hvert år, så de bør ligge som data per år, ikke hardkodes.

- **Skatt:** skattekort/tabelltrekk, **halv skatt i november**, **feriepenger** utbetalt i juni (ingen ordinær lønn/skattetrekk på samme måte), skattemelding/skatteoppgjør (restskatt/tilbakebetaling).
- **Sparing med skattefordel/egne regler:** BSU (fradrag, aldersgrense), ASK (aksjesparekonto), IPS (individuell pensjonssparing), fondskonto.
- **Formue og gjeld:** formuesskatt, rentefradrag (22 %), Gjeldsregisteret, studielån (Lånekassen).
- **Pensjon:** Norsk Pensjon / NAV, OTP fra arbeidsgiver.
- **Hverdag:** Vipps-transaksjoner (ofte dårlig beskrevet i kontoutskrift), KID-nummer, eFaktura/AvtaleGiro, faste trekk.
- **Formatering:** NOK, komma som desimaltegn, mellomrom som tusenskille (`12 345,67 kr`), dato `dd.mm.åååå`, norsk språk i hele UI-et.

## 4. Typiske funksjoner i slike apper (å velge blant)

1. Importere og kategorisere transaksjoner (regler + manuell overstyring)
2. Budsjett per kategori per måned
3. Oversikt over formue/nettoformue (kontoer, fond, bolig, gjeld)
4. Sparemål
5. Faste utgifter / abonnementer
6. Norsk skatteestimat og planlegging (halv skatt, feriepenger, BSU/IPS-fradrag)
7. Rapporter og grafer over tid

## 5. Hva vi ser etter i GitHub-repoene

- Hvordan de parser norske bankeksporter (kolonner, tegnsett, datoformat)
- Kategoriseringsregler/-lister tilpasset norske butikker og Vipps
- Datamodell for kontoer, transaksjoner, kategorier
- Hvordan de håndterer duplikater ved gjentatt import
- Hva som har gått i stykker (døde API-er som Sbanken/Nordigen)
